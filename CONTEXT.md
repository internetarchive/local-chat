# Local Chat

A floating chat widget powered entirely by an on-device language model,
answering questions grounded in context a host page provides.

## Language

**Instructions**:
The text establishing the assistant's persona and behavior. Has a sensible
built-in default; a host that sets this replaces the default entirely.
_Avoid_: System prompt, persona

**Context**:
The reference text answers must be grounded in — provided directly, auto-
extracted from matching page elements, or both combined.
_Avoid_: Grounding, reference material, source text

**Parent Session**:
The on-device model session created once per component instance, primed
with Instructions and Context. Expensive to establish, so it's created
lazily and kept alive for as long as the component is in use.
_Avoid_: Base session, root session

**Child Session**:
A session forked from the Parent Session, holding one Conversation's actual
message history. Cheap to create, since Instructions/Context priming isn't
repeated.

**Conversation**:
The back-and-forth message history held in one Child Session. Ends when the
chat is cleared.
_Avoid_: Thread

**Exchange**:
One complete user message and the Assistant's reply to it, written to
History atomically once the reply finishes. A message that never got a
reply — Superseded, errored, or the tab closed before it completed — is
never saved; an unanswered trailing question isn't worth keeping without a
way to retry it.
_Avoid_: Turn, pair, round

**History**:
The persisted collection of past Exchanges for a given storage scope,
surviving across page loads — unlike the Conversation itself, which lives
only as long as its Child Session does. Capped at a configured size,
oldest Exchange dropped first once exceeded. Restored into a freshly
forked Child Session on first Expand, so the Conversation continues from
where History left off rather than starting over.
_Avoid_: Chat log, saved messages

**Clear**:
Discarding the current Child Session and forking a fresh one from the
still-primed Parent Session — resets the Conversation without repaying the
Instructions/Context setup cost. Also purges the persisted History for the
current storage scope, so a later page load doesn't resurrect what was
just cleared.
_Avoid_: Reset, restart

**Follow-up**:
A suggested next message, generated once a response finishes, that the user
can click to send immediately.
_Avoid_: Suggestion

**Starter**:
A host-provided opening message, rendered into the transcript — the same
place a Follow-up is — before any message has been sent. Purely
declarative — never generated by the model.
_Avoid_: Bootstrap prompt, welcome prompt

**Icebreaker**:
A model-generated opening message, produced by the same mechanism as a
Follow-up but explicitly prompted as an opening suggestion grounded in
Context, rather than a reply to a prior response. Generated once per
Parent Session (right after priming completes), cached, and reused across
Conversations, since it depends only on Instructions/Context, not on any
particular exchange. Shown alongside any Starters.
_Avoid_: Opener, initial follow-up

**Empty message**:
A plain, non-interactive message shown in place of Starters/Icebreakers
when neither exists yet — replaced the instant either does, and cleared
for good once a real Exchange begins. Purely cosmetic: never a Suggestion,
never clickable, never generated by the model.
_Avoid_: Welcome message, placeholder text

**Scratch Session**:
A disposable session cloned from whichever durable session (Parent, or
Child once one exists) is current, used for a single Follow-up or
Icebreaker generation call and nothing else. Never the durable session it
was cloned from — so a Superseded call can be destroyed immediately with
no risk to the Conversation history or the Parent Session's priming, and
even a call that resolves normally never leaves the "suggest some options"
exchange itself sitting in the Conversation's own history, for something
the user may never have looked at.

**Superseded**:
The state of an in-flight Follow-up or Icebreaker generation call once a
newer user action (sending a message, in particular) has made its eventual
result pointless before it resolved. Its Scratch Session is destroyed
immediately rather than left running — a cancellation signal alone isn't
reliable enough to promptly free the model for the next call.

**Widget**:
The floating UI as a whole: an icon/button when Collapsed, a full panel
(transcript, input, Follow-ups) when Expanded.

**Collapsed** / **Expanded**:
The Widget's two visibility states.

**Trigger**:
A host-provided element, external to the Widget, that Expands/Collapses it
— wired via `trigger-selector` or the `expand()`/`collapse()`/`toggle()`
methods. Distinct from the Widget's own built-in toggle button, which isn't
a Trigger itself.
_Avoid_: Launcher, invoker

**Visual state**:
Collapsed/Expanded, plus the toggle icon's and panel's dragged position and
the panel's resized size — persisted only once the visitor actually changes
one of them from its default, and only for the current tab/session, unlike
History's durable, explicitly-cleared persistence. No dedicated affordance
clears it; closing the tab does.
_Avoid_: UI state, layout state, window state
